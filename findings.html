Why the edge cannot exist

Extractor choice dominates

Cross-repo edges scored against an answer key derived from source, which never reads extractor output.

Extractor Precision Recall · Python Recall · Go

One design decision explains the spread. CodeGraph keeps the module path on its import records; the other two discard it. Two of three tools therefore carry nothing an ETL can use, and the difference between 0.960 and 0.000 is a field, not an algorithm.

On merge-graphs

Graphify ships a merge-graphs command described as producing a cross-repo graph. Scored as its own arm, given perfect repository attribution so it is judged only on its edges, it produces zero — it namespaces every node and leaves each edge inside its source graph. The merged file already contains both endpoints of the join, including package identity and version. No pass runs over them.

What it found in production code

llm-graph-builder imports GraphDatabase, TransientError and neo4j.time directly from the driver across four files — and never declares neo4j in requirements.txt. It works only because langchain-neo4j pulls the driver in transitively, and breaks silently the day that stops being true.

src/graph_query.py → neo4j.time src/graphDB_dataAccess.py → neo4j.exceptions.TransientError src/shared/common_fn.py → neo4j.GraphDatabase dbtest.py → neo4j.GraphDatabase

Seeing this needs both halves at once: declared dependencies from manifests and actual references from source. Software-composition tools hold the manifest without the calls; a single-repo code graph holds the calls without the sibling repository.

How much of it to believe

Three extractors vote independently on every node and edge.

High agreement on what is a node; heavy divergence on what calls what. Only 15% of call edges are corroborated by all three, so a blast radius can be re-asked at a chosen evidence threshold:

graphdatascience.Graph.name 374 files impacted corroborated by all three 1 two of three 182 single extractor — verify 191

That spread is the honest uncertainty in the answer. It only becomes visible once a third opinion is in the graph.

Subsystems the repository layout hides

GitNexus and Graphify both run Leiden community detection already — per repository, so the result can only ever be intra-repo. The constraint is the projection, not the clustering.

Over the joined graph: 6,305 communities at modularity 0.879, of which 24 span more than one repository and three span all four Go repos — one covering 9,158 symbols across mimir, dskit, loki and tempo. Betweenness independently ranks InjectOrgID near the top, the same symbol the fan-out analysis ranks first. Two unrelated measures, one answer.

Where the claims stop

Read before quoting a number
  • Not “these tools can’t do cross-repo.” Graphify ships the command; it produces zero edges, but it exists.
  • Not “recall is 0.96.” That is CodeGraph on Python. Graphify is 0.254; on Go, two of three score 0.000.
  • Not “precision is always 1.000.” It is on Python; 0.999 on Go, where two false positives survive from code that shadows a package name with a variable.
  • Not “the agreement figures are clean.” On Go they are a lower bound — roughly 20,853 single-tool methods are an unfixed naming divergence rather than real disagreement.

What survives all of it: the cross-repo edges exist nowhere else, and every one carries its inference method and a confidence value.
